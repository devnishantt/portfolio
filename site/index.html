    Five bugs that have cost real companies real money. Every lab contains two versions of the same code: a common bug and my code.

    Seeing “bug reproduced” is the point, not a failure. Each lab starts on the common bug so you can watch it break. My code is the other option, and it should never break. If you make it break, email me.

      Concurrency / bank-management-system

      Withdraw the same money twice

      assert cash_dispensed <= opening_balance
      untested

      Two ATMs withdraw 60 from an account holding 100 at the same instant. Correct result: one succeeds, one is refused. The database interleaves their statements however it likes.

      1. Race with Read, then write. Usually 120 comes out of a 100 account.
      2. Pick either my code option and race again. Never more than 100.

      Idempotency / bank-management-system

      Get charged three times for one payment

      assert charges(payment_intent) <= 1
      untested

      The server charges the card, then the response is lost on the way back. The client times out and retries, exactly as a well-behaved client should. Correct result: one charge.

      1. Turn the key off (common bug) and send. You get charged three times.
      2. Turn it back on (my code) and send. One charge.

      Make a cent disappear

      untested

      1. Pick an example. The common bug column loses or invents a cent.
      2. My code column always adds up exactly, and refuses amounts like 1.005 instead of rounding them.

      Rewrite history without getting caught
